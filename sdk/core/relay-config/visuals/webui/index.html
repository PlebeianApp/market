relay-config — the one relay configuration port

One question: which relays? One port answers it, by role. The library parses the relay lists; the app's own relays, its two switches and its one configuration write stay ours; and the app's instance config is injected as data, never imported from src/.

Three groups of members, and saying which is which IS the port

the library's

Library-derived

  • userRead(pubkey) — 10002 inboxes
  • userWrite(pubkey) — 10002 outboxes
  • dmRelays(pubkey) — 10050, or undefined
  • role(role, pubkey) — 10007 / 10006 / 10012 / 10086

Parsing, marker rules and validation are the library's. No hand-rolled list parse exists here.

ours

Ours

  • instance('app'|'bug'|'cvm'|'zap')
  • outboxEnabled()
  • dmFallback() — 'refuse' by default
  • setWriteRelay(url) — a config write

The library models another party's relay lists; it has no word for this app's relays.

injected

The default layer

  • RelayDefaults — the app's slots, as data
  • instanceZap — additive, never a replacement
  • outboxEnabled, dmFallback

With no event to derive from, the instance roles answer from it — it is the floor, not a substitute.

The flow — a store subscription, never a dial

▼  the library's model / validator / getRelaysFromList
the port answers, by role
▼  no pool, no socket
