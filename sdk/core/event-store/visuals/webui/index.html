A reading guide to one module

The event store, in plain language

One module that keeps the events this app has and answers one question — what is locally true right now? — without a socket, a deadline or a promise about the network. This page explains the job, the endpoint, the measurements, and the parts that are not finished.

CHAPTER 01

What the module is — the local truth

An app that talks to relays has a second problem the relays cannot answer: what does this device already know, right now, without asking anyone? This module is that answer, and it is what an app's read path stands on before any network is involved.

The job, in one sentence. Hold the app's local truth — an id-unique set of raw events, one head per replaceable or addressable address, the three kinds of deletion, provenance marking and a count taken from its own index — and expose the single local read/write endpoint a surface asks through, with no socket, no deadline and no completeness claim.

Three words recur and are worth fixing now. An event is one published item: a post, a product listing, an order message — a NIP-01 record with an id, an author, a kind and a signature. A filter is how a caller asks for a subset of them. An address is the thing a replaceable event occupies, so that a newer version replaces an older one instead of piling up.

Built, not extracted

Two things that are easy to blur, and the spec keeps them apart deliberately:

The spec

Written at its final state — the module as it should be, not as anything is today. A Rust, Angular or Flutter version of the same module would satisfy the same contract. This is why the document names behaviour rather than code, and why it declares many implementations.

The first implementation

TypeScript, in event-store/ts/, the local half only. It is not harvested from the app: the market's stores/ndk.ts is the code this module replaces, not the code it came from. Nothing in it reads this repository, the app or a host.

Why a store before anything needs it

The module is specified at its final state and stands alone, so it can be checked without its host. That is the point: a module that cannot be checked without the app it came from has not left it. The cost is named on this page too — nothing imports it yet, and chapter 7 is honest about that.

CHAPTER 02

The local read/write endpoint

One shape, and the store is one thing that satisfies it. A relay satisfies the same shape. That is what makes compatibility between a store and an IO seam a matter of configuration rather than coupling.

The contract, in one sentence. The module exports a factory that returns an endpoint — a declared tier, a local read, a local write, a count from its own index, a local removal and a local change notification — plus the filter guard, the head rule, the view's functions, the declared support values and the spec's types. Nothing in it speaks the wire.

The members, one line each

01 tier

The declared capability: this endpoint is a local source, not a remote one, so a composition can order it first and mark provenance without knowing which module it holds.

02 read

Answers with raw events from the store's own index — descending by created_at, id-unique — and makes no completeness claim, because with no network phase there is nothing that could be incomplete.

03 write

Verifies the event and stores it before, or independently of, any relay attempt. A publication no relay took is still a local write; a verification failure is counted in refused and stored nowhere.

04 count

Counts the store and is never answered by fetching, and reports approximate: false because an in-memory index is exact. A wire COUNT belongs to a relay host, which this module is not.

05 remove

Takes an id or a filter and returns the number removed. This is the temporary, restorable deletion — see chapter 4 for what it is not.

06 changes

The local change notification: the half a caller needs to see its own writes. The subscription that spans two tiers left with the operations.

Plus the filter guard those members call, and the declared FILTER_SUPPORT and EvictionPolicy — values a test reads rather than prose. The guard is now exported, so a consumer's fake can be a differential against this module's single implementation instead of a model of it; a second implementation anywhere is a defect an export like this makes visible.

The store is a local relay

"One shape that a relay and this store satisfy alike" is the sentence that makes the composition cheap: what exists between this module and an IO seam is an endpoint a host plugs in, and compatibility between them is configuration rather than coupling.

CHAPTER 03

What it is not — the boundary it refuses to cross

A module is defined as much by what it will not do. Everything below is absent from the contract and measured absent from the code — with one permitted exception, named exactly.

What it does not know

Relay policy, the relay set, wallets, signers, user-facing text, marketplace record types. The market's ndk.ts is 1,055 lines; this module owns the event-data half of a small piece of it and nothing else.

What it does not do

It opens no socket, holds no timer, reads no host global, and never claims completeness. Its only integrity rule is the event's own id and schnorr signature — no kind schema, no content check, ever. A correctly signed event with nonsense content is stored.

Bound to the boundary

The one permitted line is a promise kept: the clock is injected and defaults to whole seconds, and the database is optional — a store with no database is fully functional. The persistence medium and the eviction floor are later increments (N3), and the seam ships as types only.

CHAPTER 04

The three kinds of deletion, told apart

Two deletions are never conflated — and NIP-40 expiry is neither. Pick one below and the panel says what it does, whether it is durable, and which measured case proves it.

Why the third one is not a deletion at all

Expiry does not touch the store. The event stays where it is, and the read excludes it — unless the caller asks for it with keepExpired, and at the exact boundary expiration === now it is already expired. That is why the module keeps three predicates rather than one: a store that treated expiry as a removal would lose data it was never asked to lose.

CHAPTER 05

The invariants, and how each was attacked on purpose

Eleven deliberate mutations, each breaking one rule in a real file, each making its named case fail, each restored byte-for-byte and re-verified by hash. A rule whose test survives a mutation that breaks it is a rule nobody has really proven.

The explorable below is the filter guard — the fail-closed predicate, exported so a consumer's fake can be a differential against it. Pick a filter and the panel says what the store answers.

M3 One head per address; the greater created_at wins, ties go to the lexicographically lower id, arrival order never decides. 1 — flip the tie-break. 2 — keep the first arrival instead of the winner. one head per address… · the collapse does not depend on the input order
M7 Identity inputs fail closed: a malformed value rejects and is never repaired; an empty list is kept and matches nothing. 3 — the rejection returns instead of throwing. 4 — empty arrays are dropped, broadening the filter. 10 — the tag-key arm stops recognising the empty list. a malformed identity value rejects… · an empty identity list matches nothing… · …answered as nothing on every surface
M9 Two deletions are never conflated, and NIP-40 expiry is neither. 5 — drop the author check, so any author's kind-5 deletes any event. 6 — flip NIP-40's boundary to <. a kind-5 deletion is honoured for its own author's event only · an expired event is excluded on read…
M2 An event matched by two filters is returned once — the id-unique union. 7 — stop deduplicating, so a twice-matched event is returned twice. an event matched by two filters is returned once
M12 Provenance is contract-visible: every event a read answers with satisfies isFromCache. 8 — stop marking provenance on read. a read's events satisfy isFromCache…
M5 + M14 No socket is required: the handle is exactly the endpoint, and the count is local. 9 — re-attach a relay edge to the handle. no socket is required…
D-O6 Any #-key list that is present and empty matches nothing and is answered as nothing, never dropped. 11 — the narrower rule: stop the general empty-#-key arm. an empty #-key list matches nothing, for every #-key…

Seven rules, eleven mutations: M7 was attacked three times and M3 and M9 twice each, because a rule with two halves — a rejection and a kept empty list; an author scope and a time boundary — needs each half broken separately or one of them is only assumed.

CHAPTER 07

What is not yet true

Read this as the honest half of chapter 6: the measurements are real, and they are all the module has. Everything below is true today and says so plainly.

The honest sentence for all of chapter 7

The module is built and measured against its own suite and its own fakes. Nothing in the repository, the app or any host imports it; its live use — which composition, which host, whether the app re-points onto it — is a later increment's decision, and this page does not make it on their behalf.

CHAPTER 08

The findings it reports rather than repairs

Six things the first implementation cannot settle on its own. Each is recorded where it bites, and the module deliberately does not invent the answer to any of them.

1 · The seam's vocabulary (E7)

The spec's block prints four members while calling the two types adopted verbatim from the library; the library's interfaces are a read interface plus three writes. The module declares its two types as the library's, which is the one-line amendment the increment carries.

2 · The removal notification has no type

The spec requires a kind-5 deletion to arrive as a removal notification, but the subscription's stream is AsyncIterable<Event>, and a removal is not an event. The module does not invent one; the obvious repair is a union, which is a spec change and the maintainer's.

3 · A trailing colon

createReplaceableAddress ends in a trailing colon for a replaceable kind with no d; the market's own deduplicationKey() does not. The module adopts the library's form so its keys and the strings it compares agree, states the exact strings in its test, and reports the spec's comment as imprecise.

4 · NIP-50, accepted and ignored

FILTER_SUPPORT is { nip91: true, nip50: false }. A search filter does not filter — the answer is the one the same filter without search gets. The lookup is given a copy of the filter without the key the implementation declares it does not honour. Reported for a decision: declare-and-accept, or reject fail-closed.

CHAPTER 09

Open questions, and how to check it in a minute

The module leaves one question genuinely open for its maintainer, and this page makes a few assumptions in plain words so they can be corrected.

How to check any of this in a minute

what command, from the assembly root
the suite cd event-store/ts && $HOME/.bun/bin/bun test
the compiler cd event-store/ts && $HOME/.bun/bin/bun run typecheck
the build evidence bash event-store/evidence/run.sh > event-store/evidence/01-build-and-tests.txt
the falsification run python3 event-store/evidence/falsify.py > event-store/evidence/02-invariant-falsification.txt
the routine python3 core/checks/check.py --root .
the evidence lint python3 core/checks/evidence.py --root .

The two evidence commands redirect because the scripts print — a script that writes its own capture cannot be run twice. Run falsify.py on its own: for the length of each mutation the tree is deliberately broken, and it restores it with a sha256 check at the end.
